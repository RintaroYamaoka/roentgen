## 決まったこと(2026-10-24)

- 解析の単位は **1 repo**。repo 内の製品境界(例 marketing-app の AdNavi / KATERU)は概要ページで検出して示す
- DB は **migration からの静的復元が既定**、`--db <url>` で実物にも繋げる(SELECT 専用・値は出力に出さない)。両方ある時は差を出す
- 差分の基準点は `--since last`(既定)/ `--since <sha|date>`
- 対象言語は **全主要言語 + Rust**。層 1(言語非依存)で全言語を動かし、層 2 のアダプタは TS/JS・Python・Rust・Go から

## 実装の状態(2026-10-24 v2・Rust)

v1(Python・正規表現)は「システムの地図」止まりで却下。v2 は Rust に作り直した。

- **エンジン**:`src/`(Rust)。extract(tree-sitter: TS/TSX/JS・Python・Rust・Go / sqlparser: SQL migration / Prisma・Drizzle・Diesel)→ graph(ノード: file / function / type / table / route / job / external / package / env / layer、辺: imports / calls / reads / writes / extends / implements / references / handles / triggers / uses / contains / exports)→ analyze(入口ごとの trace・層の辺と規則・循環・churn・hotspot・roles・tenant・tested)→ store(data/*.json + graph.db)→ render(19 ページ・13 種の SVG・コード抜粋)
- **CLI**:`roentgen analyze|render|diff|query|mcp|notes|ir`。`--db`(psql で実物)、`--since last|sha`(スナップショット / worktree)
- **Claude の段**:`narrative.json`(章)+ `.roentgen/notes/*.md`(ノード。コードのハッシュで鮮度)。`roentgen notes` が未記入・古いものを重要度順に出す
- **プラグイン**:`skills/roentgen/SKILL.md`・`bin/roentgen.sh`(バイナリの探索 → cargo → Releases)・`.claude-plugin/plugin.json`(MCP `roentgen` を登録)・`.github/workflows/release.yml`(タグで OS 別バイナリ)
- **テスト**:`cargo test --release`(fixture 4 言語 + SQL。入口・呼び出し・読み書き・型・外部・env・cron・docs・tested・規則・trace・HTML・query・diff・MCP)
- **実走**:marketing-app 3,435 src files / 87 万行 → 7 秒。関数 2 万・型 6 千・入口 365・解決した呼び出し 3.7 万
- 限界:呼び出しの解決は名前ベース(tree-sitter)。メソッド呼び出し・動的 import・外部 SDK の中は「解決できない呼び出し」として関数に残す(Tech Debt に上位)。tsc の型解決を足せば減る
