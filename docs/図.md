# roentgen ― 図のカタログ(2026-10-24)

方針:**図が主、表は根拠。** 各章は図から始まり、図の箱をクリックすると根拠の表の行へ飛ぶ。
主役は初見の読み手。差分は「同じ形式で 2 回出して見比べる」で足りるようにする。そのための条件が下の 3 つ。

## 見比べられる図の 3 条件

1. **レイアウトが決定的。** 箱の並び順は path の辞書順か固定の層順。力学的レイアウト(位置が毎回変わるもの)は使わない。箱が増減しても他の箱の相対位置ができるだけ変わらないよう、層ごとに縦に積む
2. **凡例と色が全章で同じ。** 層の色は 1 つの表で決める(入口=橙 / application・usecase=青 / core・domain=緑 / adapter・infra=紫 / ui=水色 / 外部=灰 / DB=黄)。危険の印は赤 1 色だけ
3. **数字は図の中に書く。** 辺の本数・行数・表の列数を箱と辺に直接入れる。2 回出した時に数字の違いで変化が見える

描画:ビルド時に **インライン SVG** を生成する(外部 JS に依存しない。社外 repo でも開ける)。グラフ系(依存・ER)は `dot` があれば使い、無ければ自前の層レイアウトに落とす。ダーク対応は CSS 変数で色を差す。

## 章ごとの図

| 章 | 図 | 答える問い | 形 |
|---|---|---|---|
| index | **全体図 1 枚** | このシステムは何で、何と繋がっているか | 中央に repo(製品が複数なら箱を分ける)、左に利用者、右に外部 SaaS、下に DB。各章へのリンクを箱に持つ |
| 00 概要 | 構想図 | 誰が・どの画面で・何を得るか | 利用者 → 画面群 → この repo → 結果。製品境界を点線で |
| 01 構成 | デプロイ図 | どこで動き、何に依存するか | ホスティング(Vercel / Fly / k8s)の枠の中に runtime・cron・queue。外に DB・SaaS・env キー名を線で |
| 02 データ | **ER 図** | 中心の表は何か・どう繋がるか | FK を辺。50 表超は FK 次数上位 15 を「中核」として描き、残りは表。RLS 無しは赤枠 |
| 02 データ | migration の時間線 | いつ何が足されたか | 横軸に日付、縦に migration。分割ディレクトリ(凍結)は別レーン |
| 03 流れ | 入口の地図 | 入口はどれだけあり、守られているか | 入口の種類ごとに箱を並べ、認可あり/なし/不明を色で。本数を箱に書く |
| 03 流れ | **シーケンス図 × 3〜5** | 代表的な処理はどう流れるか | 入口 → 層 → adapter → DB / 外部。層の色は共通の凡例。横に path を併記 |
| 04 依存 | **層の図** | 層は守られているか | ディレクトリ 1〜2 段目を層順に縦に積む。import の辺を本数で太さ。禁止辺は赤・違反 0 なら緑の破線で「守られている」も見せる。循環は両矢印で赤 |
| 04 依存 | モジュール図(ファイル単位) | このファイルを触ると何が壊れるか | 指定した層の中のファイルを箱、import を辺。箱に公開シンボル数と被 import 数。`--scope` で範囲を切る |
| 04 依存 | **クラス図・型図** | 業務の概念はどんな型で表されているか | class / interface / type / enum / struct / trait を箱、継承は白抜き矢印・実装は破線・型参照は実線。既定 core / domain のみ・30 シンボル上限 |
| 04 依存 | Rust / Go 用:crate・package 図 | 境界はどこか | crate / package を箱、`pub` の辺。層の図と同じ描き方 |
| 05 動き | **ヒートマップ** | 最近どこが熱いか | ディレクトリツリーをツリーマップ(面積=行数、濃さ=90 日 churn)。巨大ファイルは赤枠 |
| 05 動き | 週次の帯グラフ | 活動のリズムと触った層 | 横軸 13 週、積み上げ棒を層の色で |
| 06 壊れやすい場所 | **リスクの地図** | どこを触る時に注意するか | 04 の層の図を薄く敷き、リスク項目を赤い印で載せる(順位の数字つき)。表の行へリンク |
| 07 作法 | パイプライン図 | コードはどう本番に届くか | commit → pre-commit → PR → CI(ジョブ名)→ deploy(環境名)。無い段は点線で「無し」 |
| 08 用語集 | 語の対応図(小) | 日本語の語はコードのどこか | 語 → 型 / 表 / ディレクトリ の 3 列の対応線。多ければ表だけ |
| 09 差分 | 図は作らない | | JSON 突き合わせの表。見比べは 2 回の出力の図で人がやる |

太字 = その章の主役。初見の人は index → 00 → 02 の ER → 03 のシーケンス → 04 の層 → 04 のクラス図 の 6 枚で全体が掴める想定。

## 図に共通で載せるもの

- 右下に凡例(層の色・赤の意味)
- 左上に「sha・日付」(2 回の出力を並べた時に取り違えない)
- 箱は `path` をツールチップに。クリックで根拠の表へ
- 読めなかった要素は灰色の破線の箱で「未確認」と描く(無いのではなく読めなかった、を区別)
